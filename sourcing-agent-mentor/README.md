# Sourcing Follow-up Mentor Skill 外贸采购代理跟单导师

> 一个纯 Markdown 的 AI Agent Skill（无代码、无依赖）：把一位"15 年经验的 Sourcing 跟单主管"装进任何大模型，为采购代理/外贸从业者提供从询盘到售后的全流程跟单指导与风控决策支持。

## 这是什么

**Sourcing 采购代理**是替海外买家在中国找供应商、代采购、代验货、代出货并赚取服务收入的业务模式（对标 JingSourcing）。它与普通外贸跟单的角色立场完全相反：你代表买方，核心风险是"客户与工厂飞单"，核心资产是供应商网络与流程体系。

本 Skill 把这套业务的完整方法论工程化为一份结构化提示词，可直接安装到 WorkBuddy 等 Skill 系统，或整段粘贴给 ChatGPT / Claude 激活。

## 设计亮点（为什么它不只是"一段提示词"）

| 设计模块 | 说明 |
|---|---|
| **角色人格 + 反幻觉护栏** | 15 年跟单主管人格负责表达风格；同时内置硬约束"履历设定不是证据"——禁止 AI 把角色经验当论据，结论必须落到可验证的规则与数据 |
| **全流程知识库** | 5 阶段 × 15 环节全景图 + 三条阶段衔接铁律（钱到才动 / 书面确认才推进 / 单据随货走），每个环节含动作、表单、坑点、风控 |
| **付款时序决策表** | 用一张客户分级决策表统一全文付款规则（新客户 100% 前付 / 老客户 30%+70% 见提单副本），并明确"客户的钱永远先于工厂的钱、默认零垫资"——消除提示词内部最常见的自相矛盾 |
| **17 张标准表单库** | 询盘登记 → RFQ → 供应商背调 → 比价 → 样品台账 → PI → PO → 生产跟踪 → 验货报告 → 出货指令 → 拼柜清单 → 收付款台账 → 索赔记录 → 复盘 → 客户档案，字段级规范，可直接复制使用 |
| **风险坑点库** | 供应商坑 / 客户坑 / 付款坑 / 质量坑 / 物流坑 / 合规坑 / 变更坑 / 诈骗坑 / 资金坑，按"⚠️坑 + 规避动作"成对组织 |
| **分市场作战手册** | 欧美（认证与信任）、拉美（付款与清关）、中东（SASO/SABER 与斋月节奏）三套差异化打法 |
| **每日指令系统 + 路由规则** | 7 个指令（解难/流程/优化/10x/复盘/表单/0→1），并定义自然语言路由的优先级：风控问题永远优先于流程与机会类问题，模糊意图先确认再输出——解决 Agent 意图分类不稳定问题 |
| **AQL 抽样速查表** | GB/T 2828.1 Level II 全档位速查（2–35,000 件），小批量给出"全检更优"的实用建议 |
| **话术库真实性纪律** | 英文话术全部可复制，但禁止虚构谈判筹码（如编造"别家报价低 8%"）、不承诺无限质保，输出时自动标注"需人工核对的数字/承诺点" |
| **用户档案参数化** | 全部个人化信息集中在背景节的《用户档案》，Skill 主体为通用知识——换一个人使用只需替换一个章节 |
| **版本化修订记录** | v2.1 经外部审查后修订 15 项（矛盾规则合并、幽灵引用清理、参考数字加"待验证"标签等），全程留痕 |

## 快速开始

**方式一：WorkBuddy / Claude Code 等 Skill 系统**

```bash
# 克隆后把整个目录放入技能目录（如 ~/.workbuddy/skills/）
git clone https://github.com/<你的用户名>/sourcing-agent-mentor.git
cp -r sourcing-agent-mentor ~/.workbuddy/skills/sourcing-follow-up-mentor
```

**方式二：任意对话式 AI（ChatGPT / Claude / 通义等）**

打开 `SKILL.md`，整段复制发送给 AI，即完成激活。

**个性化（30 秒）**：编辑 SKILL.md 中"背景(Background)"节的《用户档案》——填入你的公司形态、目标市场、客单区间、资质现状，其余章节无需改动。

## 日常用法：7 个指令

| 指令 | 用途 |
|---|---|
| 【解难】+问题描述 | 根因诊断 → 方案 → 风险 → 下一步 3 件事 |
| 【流程】+所处阶段 | 全景图定位 → 当前环节任务/表单/坑 → 未来 2 个阶段的坑预告 |
| 【优化】+今日工作 | 时间使用诊断 → 可交给 AI 的事项清单 → 流程改进建议 |
| 【10x】 | 今日最高杠杆点推演（砍什么 / 建什么 / 10x 机会验证标准） |
| 【复盘】 | 得失沉淀 → 明日重点 → 可固化为 SOP 的知识点 |
| 【表单】+名称 | 输出 17 张标准表单中的任意一张（字段级，可直接用） |
| 【0→1】 | 30/60/90 天起步路线图中当前周的任务与验收标准 |

## 适用与不适用

**适用**：sourcing 采购代理、贸易代理、买手工作室；客单 USD 1,000–30,000 的多品种小批量订单；市场为欧美/拉美/中东。

**不适用**：自营出口大货贸易（角色立场与风控逻辑相反）、单票超 USD 20 万的大宗订单、需要 ERP 级系统对接的场景。

## 设计决策备忘（写给同行）

- **为什么付款规则写成决策表而不是散落在各处**：提示词内部规则冲突是 Agent 行为不稳定的主要来源之一。本 Skill 在 v2.1 审查后把付款相关表述收敛为"唯一默认表 + 冲突时以本表为准"。
- **为什么案例保留具体数字但头部加通用规则**：案例的价值在于具体，风险在于被当成标准答案。解法是"示例 + 抽象决策规则"双层结构，而不是删案例。
- **为什么风控路由优先**：跟单场景中"能不能接单/付不付款"答错的代价远高于流程问题答错，意图路由必须体现风险不对称性。
- **为什么所有行业数字标"待验证"**：提示词作者无法保证时效性的数字（佣金分档、获客成本），统一标注为参考区间并要求用使用者实际数据校准——避免"幻觉数据被当成已验证事实"。
